1. Qué es maquetar

Maquetar es traducir un diseño visual a código HTML y CSS que el navegador pueda interpretar y mostrar correctamente en cualquier pantalla.

Conviene distinguir tres roles que muchas veces se confunden:

EtapaPregunta que respondeHerramienta típica
Diseño¿Cómo se ve?Figma, Canva, Adobe XD
Maquetación¿Cómo se construye lo que se ve?HTML + CSS
Programación¿Qué hace?JavaScript, backend

La maqueta es la estructura estática y visual del sitio: todavía no tiene lógica ni datos dinámicos, pero ya se ve y se comporta como el producto final.

2. Del diseño a la maqueta

El flujo de trabajo habitual tiene tres instancias:

  1. Wireframe: boceto en blanco y negro con bloques. Define qué va y dónde, sin colores ni tipografías.
  2. Mockup: el diseño terminado, con colores, imágenes y tipografías definitivas.
  3. Maqueta: el mockup convertido en HTML + CSS funcional y responsive.

Regla práctica: nunca empieces a escribir CSS sin tener claro el wireframe. Si no sabés qué bloques hay, vas a terminar acomodando cosas a fuerza de margin y parches.

3. Primer paso: la estructura semántica

Antes del color y las medidas, se define el esqueleto HTML. Usamos etiquetas semánticas, que le dicen al navegador y a los lectores de pantalla qué significa cada bloque.

<body>
  <header>                    <!-- Encabezado: logo, título -->
    <nav>...</nav>            <!-- Navegación principal -->
  </header>

  <main>                      <!-- Contenido principal, uno por página -->
    <section>                 <!-- Bloque temático -->
      <article>...</article>  <!-- Contenido autónomo -->
    </section>
    <aside>...</aside>        <!-- Contenido complementario -->
  </main>

  <footer>...</footer>        <!-- Pie: contacto, créditos -->
</body>

Por qué importa: <div> no significa nada, <header> sí. Un sitio hecho todo con div funciona, pero es inaccesible, indexa peor y es más difícil de mantener.

4. El modelo de caja

Todo elemento HTML es una caja rectangular con cuatro capas, de afuera hacia adentro:

margin — separa la caja de sus vecinas
border — el borde
padding — espacio interno
contenido

Ajuste obligatorio al inicio de todo proyecto:

*, *::before, *::after {
  box-sizing: border-box;   /* el width incluye padding y border */
  margin: 0;
  padding: 0;
}

Sin border-box, un elemento con width: 300px y padding: 20px mide en realidad 340 px, y ahí empiezan los desbordes.

5. Cómo se acomodan las cajas

5.1 Flujo normal

Por defecto, los elementos de bloque (div, p, section) se apilan uno debajo del otro y ocupan todo el ancho. Los en línea (span, a, strong) se acomodan uno al lado del otro y solo ocupan lo que necesitan.

5.2 Flexbox — una dimensión

Sirve para distribuir elementos en una fila o una columna: barras de navegación, tarjetas alineadas, centrados.

.nav {
  display: flex;
  justify-content: space-between;  /* eje principal */
  align-items: center;             /* eje cruzado */
  gap: 1rem;                       /* separación entre hijos */
}

5.3 Grid — dos dimensiones

Sirve para el layout general de la página: filas y columnas al mismo tiempo.

.contenedor {
  display: grid;
  grid-template-columns: repeat(3, 1fr);  /* 3 columnas iguales */
  gap: 1.5rem;
}

Criterio de elección: Grid para la estructura de la página, Flexbox para el contenido dentro de cada bloque. No compiten, se combinan.

<div class="layout">

  <nav class="menu">Navegación</nav>
  <main class="principal">Contenido</main>
  <aside class="lateral">Barra lateral</aside>
  <footer class="pie">Pie de página</footer>

.layout {
  display: grid;
  min-height: 100vh;
  grid-template-columns: 200px 1fr 250px;
  grid-template-rows: auto auto 1fr auto;
  grid-template-areas:
    "cabecera cabecera  cabecera"
    "menu     principal lateral"
    "menu     principal lateral"
    "pie      pie       pie";
  gap: 1rem;
}

.cabecera  { grid-area: cabecera; }
.menu      { grid-area: menu; }
.principal { grid-area: principal; }
.lateral   { grid-area: lateral; }
.pie       { grid-area: pie; }

La propiedad grid-template-areas permite dibujar el layout dentro del CSS: se lee igual que se ve en pantalla.

7. Maquetación responsive

Un sitio tiene que funcionar en celular, tablet y escritorio.

Mobile first

Se escribe primero el CSS para pantallas chicas y después se agregan reglas para pantallas grandes. Es más simple agregar complejidad que sacarla.

/* Base: celular */
.layout {
  display: grid;
  grid-template-areas:
    "cabecera"
    "menu"
    "principal"
    "lateral"
    "pie";
}

/* Tablet en adelante */
@media (min-width: 768px) {
  .layout {
    grid-template-columns: 200px 1fr;
    grid-template-areas:
      "cabecera  cabecera"
      "menu      principal"
      "menu      lateral"
      "pie       pie";
  }
}

/* Escritorio */
@media (min-width: 1024px) {
  .layout {
    grid-template-columns: 200px 1fr 250px;
  }
}

Etiqueta obligatoria en el head

Sin esto, el celular simula una pantalla de escritorio y las media queries no funcionan:

<meta name="viewport" content="width=device-width, initial-scale=1.0">

Por qué el porcentaje no alcanza

Es un error común pensar que maquetar con % es lo mismo que maquetar responsive. No lo es, y conviene entender por qué antes de usarlo.

  1. Se calcula sobre el padre, no sobre la pantalla. Si el contenedor padre no tiene un ancho definido, el porcentaje del hijo no resuelve nada. Una cadena de porcentajes anidados se vuelve imposible de rastrear.
  2. No define puntos de quiebre. Una columna con width: 33% sigue midiendo el 33 % en un celular de 360 px: son 120 px, ilegibles. El porcentaje escala, pero nunca reordena, y reordenar es justamente lo que necesita el diseño responsive.
  3. Los márgenes y rellenos verticales se calculan sobre el ancho. Es la trampa más frecuente.
  4. No sirve para tipografía. font-size en % hereda en cascada y se multiplica: dos elementos anidados al 90 % terminan en 81 %. Para texto se usa rem.
/* Comportamiento contraintuitivo */
.caja { padding-top: 10%; }   /* padre de 800px de ancho → 80px arriba */

Qué usar en su lugar

Para columnas, fr con minmax() reparte el espacio y además impide que un bloque se achique más allá de lo legible:

.tarjetas {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(280px, 1fr));
  gap: 1.5rem;
}

Esa sola línea acomoda tres tarjetas en escritorio, dos en tablet y una en celular, sin escribir ni una media query.

Para tamaños que necesitan escalar de forma continua, clamp() define mínimo, valor preferido y máximo:

h1 { font-size: clamp(1.75rem, 5vw, 2.75rem); }
.contenedor { padding: clamp(1rem, 3vw, 1.5rem); }

Para el ancho de lectura, ch junto a max-width es más preciso que cualquier porcentaje:

p { max-width: 70ch; }   /* corta la línea en ~70 caracteres */

Dónde el porcentaje sí es la herramienta correcta

img { max-width: 100%; height: auto; }   /* imagen fluida: técnica estándar */
input, table { width: 100%; }            /* ocupar el ancho del padre */

En esos casos el padre siempre tiene un ancho conocido y lo único que se busca es «no te pases del contenedor». Ahí el porcentaje es exacto y no hay reemplazo mejor.

% es una unidad de proporción, no una técnica de diseño adaptativo. El responsive lo hacen las media queries, fr con minmax(), clamp() y rem. El porcentaje acompaña, no conduce.

Imágenes fluidas

img {
  max-width: 100%;
  height: auto;
  display: block;
}

8. Accesibilidad y buenas prácticas

  • Un solo <h1> por página, y jerarquía de títulos sin saltos.
  • alt descriptivo en todas las imágenes con contenido.
  • Contraste mínimo de 4.5:1 entre texto y fondo.
  • Nombres de clases con significado: .tarjeta-producto, no .caja-azul-2.
  • CSS en archivo externo, nunca estilos en línea.
  • Áreas clicables de al menos 44×44 px en móvil.
  • Foco visible al navegar con teclado.

10. Checklist de una maqueta terminada

  • Estructura semántica correcta.
  • HTML y CSS validados en validator.w3.org.
  • meta viewport presente.
  • Se ve bien en 360 px, 768 px y 1280 px de ancho.
  • Sin scroll horizontal en ninguna resolución.
  • Todas las imágenes con alt.
  • Contraste y jerarquía tipográfica coherentes.
  • CSS externo y organizado.

11. Actividad práctica

Consigna: a partir del wireframe entregado, maquetar una página de inicio con encabezado, menú de navegación, sección de tres tarjetas, barra lateral y pie.

Requisitos técnicos

  • Grid para el layout general y Flexbox para las tarjetas.
  • Tres breakpoints (360, 768 y 1024 px), con enfoque mobile first.
  • HTML semántico, sin div innecesarios.
  • Un único archivo estilos.css externo.
  • Sin frameworks: nada de Bootstrap ni Tailwind.

Entrega: repositorio de GitHub con historial de commits que muestre el proceso, más capturas de las tres resoluciones.
